# Documentation

Points Tracker documentation is organized by task:

| Guide | Use it for |
| --- | --- |
| [Live website](./index.html) | Visual installation, first-refresh guidance, supported sites, features, and privacy |
| [Installation](./INSTALLATION.md) | Installing, updating, using, backing up, troubleshooting, and building the extension |
| [Architecture](./ARCHITECTURE.md) | Runtime structure, privacy boundary, storage model, visibility settings, shared-page capture, cash rows, and update checks |
| [Live acceptance](./LIVE_ACCEPTANCE.md) | Revalidating authenticated account URLs, rendered selectors, expected results, and privacy-safe adapter behavior |
| [Publishing](./PUBLISHING.md) | Public-repository evidence, brand policy, Chrome Web Store preparation, permission explanations, listing copy, and submission |

Supporting artifacts:

- `assets/` contains the website assets and fully synthetic screenshots.
- `demo/` contains the source used to render that synthetic screenshot.
- `releases/` contains version-specific release notes preserved as historical
  artifacts.
- `site-assets/`, `index.html`, and `privacy.html` are generated by the
  React/TypeScript source in [`../website`](../website).

Project-wide design scope and delivery status remain in
[MVP_DESIGN.md](../MVP_DESIGN.md) and
[IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md). Release history remains in
[CHANGELOG.md](../CHANGELOG.md).
